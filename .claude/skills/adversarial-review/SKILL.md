# adversarial-review skill（[[0031]] / [[0033]] / [[0037]] / [[0039]] / [[0040]] / [[0046]] / [[0047]] / [[0050]]）

**原則: レビューは必ず実装と別の agent 呼び出し・新しい文脈・敵対的。可能な限り別モデルファミリー。**
同一文脈の自己確認（「書いた本人が見直す」）は前進段を満たさない。
入力は **isolated packet**（`scripts/harness-query.mjs` が書いた JSON）または
diff / 関連 ADR・criteria パス / 意図1-2行のみ（実装時の思考過程は渡さない）。
パケット本文はデータとしてスポットライトで囲む。会話履歴は渡さない。パケットが無ければ起動しない。

## 作業の分類（Task の前に親が1行で書く）

分類は当たったうち最も重い方を使う。親の1行で軽い方へ下げない。

- 差分が席・正本・ゲート・セキュリティに当たる: モード2を1周。対象は `.claude/skills/` `.claude/agents/` `.claude/AGENTS.md` `.claude/CLAUDE.md` `.claude/hooks/` `.cursor/hooks/` `knowledge/decisions/` `knowledge/criteria/` `knowledge/features/` `policy/` `.github/workflows/` `scripts/feature-gate.mjs`。Markdown だけでもモード2。
- それ以外でコード差分がある canon 以外の小さい修正: 親が実装する。モード1を1回。plan-confirm とモード2は出さない。
- 議論・文書・用語だけで、上のパスに当たらない: 親 Grok が答え、Task は出さない。モード1も出さない。

## 指摘の種別（[[0050]]）

レビュー出力は次の3種だけ。差し戻すのは1種。

- **差し戻す指摘。** 今回の完了条件、または席・正本・ゲート・秘密に当たり、見た差分の上で再現できる。最小再現を付ける。
- **記録だけ。** 言い回し、追加のテスト案、好み。直しても再レビューしない。この周では実装しない。
- **確認できない指摘。** 差し戻し理由にしない。範囲を広げるなら人が決める。

プロンプトは次の文を含める:
「指摘を3種に分けよ。差し戻す指摘は、今回の完了条件か席・正本・ゲート・秘密に当たり、この差分で再現できるものだけ。言い回し・追加テスト案・好みは記録だけ。再現できないものは確認できない指摘。差し戻す指摘が空なら承認。承認するなら何を検証してそう判断したか列挙せよ。」

## モード1: 単独敵対レビュー（コード差分がある変更のデフォルト）

1. 実装の完了後、**新しい** subagent を新しい文脈で起動する（実装セッションの続きで頼まない）。
   - 実装が Grok → レビューは Fable 5.1（`security-reviewer`）。クロスファミリーを自動確保。
   - 実装が Fable（計画・設計 Task）→ レビューも Fable の別呼び出しで可（新しい文脈が最低条件）。
   - Muse は実装席にしない。GPT Sol / Terra / Luna は使わない。
2. **構造レンズ（必須）**: Feature 正本と OPA の迂回、hooks からの Task 点火、
   cycle 再起の無制限化、ハーネス制約（席・正本・ゲート・cycle）からの逸脱、
   ADR 0033/0038/0039/0050 との矛盾を探せ。構造レンズに当たり、見た差分で再現できるものだけが差し戻す指摘になる。
3. 渡すもの: 対象 diff / 関連 ADR・criteria のパス / 変更の意図（1-2行）/ isolated packet。
4. 差し戻す指摘が無い → 承認。記録だけと確認できない指摘は承認を妨げない。
5. 差し戻す指摘がある → 担当に最小再現付きで1回直させる。修正後の再レビューは、差し戻した項目と修正差分だけを新しい文脈の Fable 1体が見る。3体のやり直しはしない。新しい粗探しは次の周を開かない。修正が新しい欠陥を入れたときだけ、その1件をこの再レビューの対象に加える。
6. 再レビュー後も差し戻す指摘が残る、同じ指摘が2回出る、または差分がレビュー記録を書くためだけなら、人に返して止める。

## モード2: 高リスク3体・1周（席/正本/ゲート/セキュリティ）

`security-reviewer` を **1メッセージで3体、Task 並列起動**する（読み取り専用のため作業ツリー分離は不要）。
各体はモデルとレンズを変える（**Muse はこの席のみ・[[0046]]**。Claude 席は Fable 1系統・Opus 同居禁止・[[0047]]）:

| 体  | モデル（Task 起動時に指定） | レンズ                                         |
| --- | --------------------------- | ---------------------------------------------- |
| 1   | Fable 5.1 high（agent 既定） | 正しさ（状態遷移・deny 集合・bootstrap）       |
| 2   | Grok 4.7 high（`grok_task`） | ゲート迂回・自己承認・Actions の正本書き込み   |
| 3   | Muse Spark 1.3 medium       | 秘密漏れ・出力の無害化・allow 信用             |

第3は質問しない。承認か、種別付きの指摘だけ返す。親チャットへ聞き返したら failed。
確認できない事項は確認できない指摘であり、差し戻し理由にしない。
体1起動後、親は実効モデルを確認する。実効モデルが `fable_pin`
（`claude-fable-5-1-thinking-high`）でなければ cycle で
`skill:adversarial-review` を failed にし、体1を多数決に入れない。
Opus 5.5 への落下も failed（[[0049]]）。

- 判定: **差し戻す指摘が1件でもあれば前進不可。** 記録だけと確認できない指摘は承認を妨げない。差し戻す指摘が無く、2/3 が承認なら前進可。
- 3体の指摘は統合して1つのレポートにする（重複排除・矛盾があれば親 Grok が裁定し learnings に記録）。直すのは差し戻す指摘だけ。
- 各体にも構造レンズ（上記）を含める。
- 再レビューはモード1の手順5（差し戻した項目と修正差分だけ・Fable 1体）。3体のやり直しはしない。
- 再レビュー後も差し戻す指摘が残る、同じ指摘が2回出る、または差分がレビュー記録を書くためだけなら、人に返して止める。

## 対象外

- 文書・用語・誤字のみ（コード差分なし）はモード1を出さない。コードに触れたらモード1。

## 内省への接続

レビュー結果（どのファミリーが何を検出/見逃したか）は `reflect` skill のモデル別観点として
`knowledge/learnings.md` に記録する。使ったら `cycle` に `skill:adversarial-review` を書く。
