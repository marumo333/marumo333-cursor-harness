# adversarial-review skill（[[0031]] / [[0033]] / [[0037]] / [[0039]] / [[0040]] / [[0046]] / [[0047]]）

**原則: レビューは必ず実装と別の agent 呼び出し・新しい文脈・敵対的。可能な限り別モデルファミリー。**
同一文脈の自己確認（「書いた本人が見直す」）は前進段を満たさない。
入力は **isolated packet**（`scripts/harness-query.mjs` が書いた JSON）または
diff / 関連 ADR・criteria パス / 意図1-2行のみ（実装時の思考過程は渡さない）。
パケット本文はデータとしてスポットライトで囲む。会話履歴は渡さない。パケットが無ければ起動しない。

## モード1: 単独敵対レビュー（全変更のデフォルトゲート）

1. 実装 subagent の完了後、**新しい** subagent を新しい文脈で起動する（実装セッションの続きで頼まない）。
   - 実装が Grok → レビューは Fable 5.1（`security-reviewer`）。クロスファミリーを自動確保。
   - 実装が Fable（計画・設計 Task）→ レビューも Fable の別呼び出しで可（新しい文脈が最低条件）。
   - Muse は実装席にしない。GPT Sol / Terra / Luna は使わない。
2. プロンプトは**敵対的**に書く。「チェックして」ではなく:
   「この差分を壊せ。間違っている箇所・抜けている境界事例・攻撃可能な入力を探せ。
   問題が見つからない場合のみ承認。承認するなら何を検証してそう判断したか列挙せよ」
3. **構造レンズ（必須）**: Feature 正本と OPA の迂回、hooks からの Task 点火、
   cycle 再起の無制限化、ハーネス制約（席・正本・ゲート・cycle）からの逸脱、
   ADR 0033/0038/0039 との矛盾を探せ。
4. 渡すもの: 対象 diff / 関連 ADR・criteria のパス / 変更の意図（1-2行）。
5. 指摘あり → 担当 agent に最小再現付きで差し戻し（前進不可）。修正後は**再レビュー**（同じ手順で新しい文脈）。

## モード2: 高リスク3体・3ファミリー多数決（入場/再起/セキュリティ/アーキ）

`security-reviewer` を **1メッセージで3体、Task 並列起動**する（読み取り専用のため作業ツリー分離は不要）。
各体はモデルとレンズを変える（**Muse はこの席のみ・[[0046]]**。Claude 席は Fable 1系統・Opus 同居禁止・[[0047]]）:

| 体  | モデル（Task 起動時に指定） | レンズ                                         |
| --- | --------------------------- | ---------------------------------------------- |
| 1   | Fable 5.1 high（agent 既定） | 正しさ（状態遷移・deny 集合・bootstrap）       |
| 2   | Grok 4.7 high（`grok_task`） | ゲート迂回・自己承認・Actions の正本書き込み   |
| 3   | Muse Spark 1.3 medium       | 秘密漏れ・出力の無害化・allow 信用             |

第3は質問しない。承認か差し戻しだけ返す。親チャットへ聞き返したら failed。
確認できない事項は差し戻し理由として列挙する。不確実は承認にしない。
体1起動後、親は実効モデルを確認する。実効モデルが `fable_pin`
（`claude-fable-5-1-thinking-high`）でなければ cycle で
`skill:adversarial-review` を failed にし、体1を多数決に入れない。
Opus 5.5 への落下も failed（[[0049]]）。

- 判定: **過半数（2/3）が承認するまで前進不可**。1体でも重大指摘を挙げたら多数決に関係なく差し戻し。
- 3体の指摘は統合して1つの差し戻しレポートにする（重複排除・矛盾があれば親 Grok が裁定し learnings に記録）。
- 各体にも構造レンズ（上記）を含める。

## 対象外

- 文書・誤字のみ（コード差分なし）はモード1省略可。コードに触れたら必須。

## 内省への接続

レビュー結果（どのファミリーが何を検出/見逃したか）は `reflect` skill のモデル別観点として
`knowledge/learnings.md` に記録する。使ったら `cycle` に `skill:adversarial-review` を書く。
