# ADR 0050: レビュー指摘は3種、再レビューは1回

- 状態: 提案
- 日付: 2026-09-23
- 改正対象: 敵対レビューの再実行手順（skill）。席ピン（[[0047]] / [[0049]]）は変えない。廃止ではない
- 背景:
  親は指摘を直すたびに差分全体を新しい文脈でレビューさせ、3体が 5 周前後まで回った。
  #15 はユーザー文 49 字に Task 19。#13 は Task 48。終盤の差分は席の実装ではなく、
  誰がレビューしたかの記録だった。手順が「問題が見つからない場合のみ承認」と
  「指摘があれば同じ手順で再レビュー」になっており、直すたびに粗探しが開く。
- 調査:
  - CR-Bench（arXiv:2603.11078）: 1回レビューの信号対雑音比 5.11・再現率 27.01%。
    取りこぼしを探す Reflexion は再現率 32.76%、信号対雑音比 1.95。
    小さいモデルは 2.89 から 0.91。
  - Looping Is Not Reliability（arXiv:2607.24604）: 強制改訂の現在の正しさは
    1回目 0.820 から 2回目 0.673。一度は正しかった割合は 0.847。
  - If It's Not Buggy, Don't Fix It（arXiv:2609.10123）: 正しいプログラムを壊す率は
    直す率以上。1箇所ずつの修正は同じ変更を足して消す循環に入る。
  - Is Three the Magic Number?（arXiv:2607.05197）: テストやコンパイルのような
    根拠のある修復は最初の 3〜4 回で伸びが尽きる。レビューコメントは根拠が弱い。
  - Multi-Agent Debate（EMNLP 2024）: 大半は 1 周で足り、続けさせると成績が落ちる。
    MAR（arXiv:2512.20845）は議論を 2 周で打ち切る。
  - Google eng-practices: 全体として良くなれば承認し、Nit は今回の必須にしない。
  - Codex #42130 / #38375: 指摘を直して push すると再レビューが上限なしで回る。
    レビュー出力は助言であり、完了条件と見た差分に結び付くものだけが差し戻せる。
- 決定:
  1. **指摘は3種。** 差し戻す指摘（完了条件、または席・正本・ゲート・秘密に当たり、
     見た差分で再現できる）。記録だけ（言い回し、追加テスト案、好み）。
     確認できない指摘（この差分で再現できない。差し戻し理由にしない）。
  2. **再レビューは1回。** 見るのは差し戻した項目と修正差分だけ。
     新しい粗探しは次の周を開かない。修正が入れた新しい欠陥だけをその1回の対象に加える。
     高リスクの初回は 3体1周。再レビューで 3体のやり直しはしない。Fable 1体が見る。
  3. **止める条件。** 再レビュー後も差し戻す指摘が残る、同じ指摘が2回出る、
     または差分がレビュー記録を書くためだけなら、人に返して止める。
  4. **Task の前に分類する。** 当たったうち最も重い方を使う。親の1行で軽い方へ下げない。
     席・正本・ゲート・セキュリティのパス（skill / agent / AGENTS / CLAUDE / hooks /
     decisions / criteria / features / policy / workflows / feature-gate）は
     Markdown だけでもモード2。それ以外の小さい修正は親が実装し、Fable を1回。
     議論・文書・用語でそれらのパスに当たらないときだけ親 Grok のみ。
  5. **席ピンは変えない。** 親 Grok 4.7、計画/レビュー Fable 5.1、検証/内省 Opus 5.5、
     第3 Muse。Composer を前段の判定席にしない（[[0044]]）。
  6. **適用経路。** F-0015 は `proposed`（出生規則）。同一 PR の canon 適用は
     F-0001（`in_progress` / `supersede_adr: true`）の被覆。
- 結果: レビューは初回と、差し戻した項目の確認1回で止まる。記録だけの指摘は周を開かない。
