# ADR 0051: 正解は型と振る舞いの契約

- 状態: 提案
- 日付: 2026-09-27
- 改正対象: 完了条件の「正しさ」。席ピン（[[0047]] / [[0049]]）と指摘の3種（[[0050]]）は変えない。廃止ではない
- 背景:
  設計を文章で残し、実装がそれに沿うかを別のモデルが読むと、読むたびに新しい指摘が出る。
  指摘を直すと差分が変わり、次の読みは別の指摘を見つける。終了条件が「指摘がゼロ」だと周が終わらない。
  型と、入力に対する出力を先に書いて機械が判定すれば、同じ赤は直るまで同じ赤のままである。
- 決定:
  1. **正解は契約。** 契約は型（署名）と振る舞い（入力と出力の組、または期待する例外）である。
     LLM の「問題が無い」は正解ではない。
  2. **型の判定は tsc --noEmit。** 実装は契約の型に代入できること。
     戻り値の型が違えば赤。`contracts/*.contract.ts` が契約、`scripts/lib/*.ts` が実装。
  3. **振る舞いの判定は実行。** 契約に書いた引数で関数を呼び、出力か例外が一致すること。
     `node scripts/contract-check.mjs` が両方を見る。feature-gate はこれを通らないと成功にしない。
  4. **レビューは契約の代わりをしない。** 契約が緑の振る舞いについて差し戻さない。
     差し戻せるのは、型と振る舞いでは赤にならないもののうち、席・正本・ゲート・秘密に当たり、
     見た差分で再現できるものだけ（[[0050]]）。
  5. **起動回数は機械が拒否する。** 新しい周の `skill:adversarial-review` は 4 まで。
     4 は初回3体と再確認1回。merge-base に既にある周は、その回数を超えて増やせない。
     超えたら `node scripts/review-cap-check.mjs` が失敗し、feature-gate も失敗する。
- 結果: 正しさは型検査と振る舞いの緑で決まる。レビューは契約が表現できない危険だけを、回数の上限つきで見る。
